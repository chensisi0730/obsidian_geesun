# Plan Sync — 规划文档 → 开发计划 Excel

## 文件地图（CATL 看机项目）

| 角色 | 路径 | 说明 |
|------|------|------|
| 源页面 | `wiki/机器人/CATL 看机双足人形机器人开发规划.md` | 唯一事实来源。同步时**只读**；仅当用户明确要求一致性修复时才改 |
| 目标文件 | `wiki/机器人/CATL 看机双足人形机器人开发计划.xlsx` | 生成物，绝不手改，永远由数据模块重生成 |
| 数据模块 | `scripts/plan-sync/pd1.py`(P1+P2) / `pd2.py`(P3+P4) / `pd3.py`(P5+P6+RISKS+INFO) | 行元组列表，是 xlsx 的唯一数据源 |
| 生成器 | `scripts/plan-sync/gen_plan.py` | openpyxl 生成 + 内置验证输出；自定位、任意 cwd 可运行 |

**注意**：用户可能在 `/tmp/pd*.py` 维护另一份数据模块副本（本工作区曾发生 /tmp 版本被整体重写）。同步前先 `diff scripts/plan-sync/pd1.py /tmp/pd1.py`，以**较新且与 xlsx 一致**的版本为准；两边都旧时以仓库副本为准并在报告中说明。

### 数据结构
- 任务行元组（9 列）：`(序号, 关键阶段, 任务事项, 开始日期, 结束日期, 责任人, 备注, 风险项目文本或"", R编号或"")`；`-M` 结尾为里程碑行。
- `RISKS` 元组（8 列）：`(风险ID, 风险项, 概率, 影响, 缓解措施, 关联任务, 责任阶段, 状态)`。
- `INFO` =「说明与图例」工作表内容，含最后一行「版本记录」（每次 V 级变更追加一行）。

## 同步流程（按序执行）

1. **全文读取源页面**：read_files 读完整文件；输出被截断时用 start_line/end_line 分段补齐。整理各 Phase「关键任务」bullet、里程碑表、风险表、角色定义表的当前清单。
2. **与数据模块 diff**（先读 `scripts/plan-sync/pd*.py`）：逐条分类变化——描述改写 / 新增项 / 删除项 / 移入移出阶段 / 日期基线变化 / 责任人变化 / 风险表变化；并对照 `wiki/操作日志.md` 上次同步点，区分「用户新变更」与「上一轮修复被用户保存版本覆盖而丢失」（后者需判断是否重新应用：用户明确请求过的（如角色定义）应补回，措辞级以文档内部一致性为准）。
3. **写行锚点补丁脚本**（editor 创建 `/tmp/patch_vN.py`，miniconda python 执行）：
   - 每操作形如 `(anchor子串, [替换行])`；断言 anchor 在文件中**恰好命中 1 次**，否则整体中止不写文件。
   - 删除中间项并重编号时：**从大 ID 往小 ID 顺序处理**，避免新插入行与待处理行的锚点碰撞；anchor 用「ID + 阶段名 + 描述开头」保证唯一。
   - 重编号必须级联更新所有引用：`RISKS` 的关联任务列、任务行风险登记列。
4. **重新生成**：`~/miniconda3/bin/python scripts/plan-sync/gen_plan.py`（系统 python 无 openpyxl，必须 miniconda）。下拉范围 K/H 列按行数自动计算，无需手改。
5. **验证**：openpyxl 读回所有被改动单元格 + 数据行总数；核对 gen_plan 内置验证输出（DV range `K4:K<末行>`、风险 `H4:H<末行>`）。
6. **追加操作日志**到 `wiki/操作日志.md`（顶部插入新条目：查阅页面 / xlsx 变更明细 / 行数变化 / 核心洞察）。
7. **报告**：diff 表 + 「保持不动」项（未评级草稿风险、用户原文措辞如“4 人产能瓶颈”）+「所做假设」（新增任务的日期/责任人推导依据）。

## 护栏

- **并发编辑是本工作区常态**：源页面与数据模块都可能被用户在会话间隙重写（风格、ID、列语义都会变）。补丁前必须即时读取最新内容重建 anchor；anchor 未命中 → 先重读文件，绝不凭旧记忆重试。
- **序号稳定优先**：新增项追加到该阶段末尾（`-M` 行之前）；只有删除中间项才重编号，且必须在「说明与图例」版本记录中写明 ID 映射（如 `OpenARM→T7、工作站采购→T8`）。
- **不编造数据**：未评级的风险概率/影响留空；新增任务日期默认取阶段窗口内合理区间并在备注注明（“由 Phase X 移入”“新增”）；责任人按「人员分工」角色定义推导。
- **不动的文件**：原规划快照 `wiki/机器人/CATL 看机双足人形机器人开发规划.xlsx`、空占位符 `开发计划.excel`。
- **不静默覆盖用户版本**：发现上一轮一致性修复丢失时，补回“用户明确请求过”的部分并在报告逐条说明；文档 frontmatter `updated` 随一致性修复同步更新。

## 常见坑（本工作区实测）

- 终端输出常无法捕获 → 命令输出重定向到 `/tmp/xx.log` 再 cat / read_files。
- editor 对多行长中文 old_text 批量替换易因并发编辑失败 → 优先写 `.py` 补丁脚本（editor create + miniconda python 执行），每步断言。
- openpyxl 一律用 `~/miniconda3/bin/python`。
